# Отрисовка Sovereign 0.14

## Что изучено

Использованы открытые описания и исходники, а не предположения о закрытом движке Google Maps или HoI4:

- [Архитектура MapLibre GL JS](https://github.com/maplibre/maplibre-gl-js/blob/main/ARCHITECTURE.md): подготовка геометрии, подписей и индексов в worker-потоках; передача готовых буферов; GPU-отрисовка с повторным использованием ресурсов.
- [OpenGL-рендерер OpenTTD](https://github.com/OpenTTD/OpenTTD/blob/master/src/video/opengl.cpp): текстуры, буферы вершин, кэш спрайтов и вывод через графический API в настоящей стратегии. Это конкретный пример разделения подготовки изображения и показа кадра, не обещание одинакового FPS разных игр.
- [Microsoft: Direct2D overview](https://learn.microsoft.com/en-us/windows/win32/direct2d/direct2d-overview): ускоренная 2D-отрисовка и взаимодействие с существующим GDI-приложением. Простой перенос полного GDI-снимка в новую текстуру каждый кадр оставляет основную работу на CPU.
- [Godot: Thread-safe APIs](https://docs.godotengine.org/en/stable/tutorials/performance/thread_safe_apis.html): потоки не должны одновременно менять используемое интерфейсом состояние. Нужны явное владение данными и публикация результата.

Главный вывод: перемещение камеры должно менять координаты уже готовых ресурсов. Подготовка новых участков и расчёт мира не должны быть обязательной частью каждого движения мыши. Низкая общая загрузка 12 логических процессоров не исключает ограничения одного потока окна.

## Реализация

На Windows по умолчанию включается OpenGL 2.1 через OpenTK. WinForms сохраняет управление окном, ввод и существующие панели. При ошибке графического контекста игра возвращается к GDI+. Режим можно переключить в настройках без замены кампании. На Linux автоматическим остаётся совместимый режим; GPU-проверки включают OpenGL явно.

1. Географические тайлы подготавливает отдельный worker. Одна новая порция подписей обрабатывается в UI за кадр. Метрики текста измеряются при создании окна и переиспользуются при масштабировании.
2. Готовые тайлы загружаются в текстуры и остаются в GPU-кэше. При движении камеры меняются координаты прямоугольников; готовая география не проходит через `Graphics.DrawImage` каждый кадр. Есть предзагрузка пояса вокруг экрана и обзорная подложка как для CPU-промаха, так и для ещё не загруженной GPU-текстуры.
3. Панели интерфейса — отдельная прозрачная текстура, обновляемая при изменении UI или данных. Движение карты само по себе её не обновляет. Подсветка, маркеры и маршруты хранятся как команды в мировых координатах с запасом вокруг экрана. Клики проецируются на текущую камеру.
4. `PresentGpu` вызывается планировщиком непосредственно, без ожидания обычной низкоприоритетной очереди `WM_PAINT`. В покое непрерывная перерисовка не требуется. Доступны 30/60/90/120/144/165/240, отсутствие лимита и частота монитора с запросом VSync. Поддержка синхронизации зависит от драйвера.
5. В GPU-режиме один worker рассчитывает следующий игровой день. Пока он владеет изменяемым состоянием кампании, UI использует готовые снимки цветов, панелей и команд. Камера не берёт блокировку симуляции. Приказы, переходы и сохранение выполняются в порядке поступления после завершения дня. Закрытие также ждёт завершения. Совместимый GDI-режим сохраняет прежний последовательный расчёт.
6. Изменение тематического слоя готовит новую обзорную подложку в фоне. Первая подложка при открытии карты создаётся синхронно; это начальная загрузка. Уже показанная подложка сохраняется до готовности замены.

Бюджеты: CPU-кэш — 96 тайлов, GPU-кэш — 256 МиБ; обычные загрузки — 4 МиБ за кадр. Один крупный слой разрешён при пустом бюджете, иначе он никогда бы не загрузился. Обзорная подложка и изменившийся HUD имеют приоритет и могут превышать бюджет загрузки кадра. Большой HUD, новый фронт/подсветка и перестройка UI ещё могут занимать время на CPU. Это ускоренный композитор растровых ресурсов, а не полностью новый векторный игровой движок.

## Воспроизведение проверки

```powershell
Sovereign.exe --gpu-test artifacts/gpu
Sovereign.exe --gpu-pan-benchmark artifacts/pan60.txt
Sovereign.exe --gpu-pan-benchmark --165 artifacts/pan165.txt
Sovereign.exe --gpu-live-benchmark artifacts/live60.txt
```

Для запуска того же сценария против старого exe в Mono:

```bash
mcs -define:PROBE_STANDALONE -r:System.Windows.Forms -r:System.Drawing -r:System.Core -out:/tmp/FrameProbe.exe src/FramePacingProbe.cs
bash scripts/with-display.sh mono /tmp/FrameProbe.exe /path/to/old/Sovereign.exe /tmp/before.txt
# После пути отчёта можно добавить --live или --165.
```

Диагностика сохраняет исходный `settings.xml`. Тесты GPU проверяют настоящий framebuffer, попадание мышью через дочерний GL-контрол, выбор страны, повторное использование HUD/текстур, масштабирование, окно/полный экран, восстановление рендерера, сохранение и закрытие при занятой симуляции. Искусственно удерживаемый worker не мешает показать десять кадров. Результат дня сравнивается с синхронным движком целиком через сериализацию.

Замер движения использует реальный цикл сообщений, ввод с независимого таймера и не более одного ожидающего события. При ускоренном сценарии политические уведомления автоматически возвращаются на карту с возобновлением времени; данные события сохраняются. Он считает как презентации, так и кадры с реально изменившейся камерой, сохраняет p95, максимум и количество задержек. Это интервалы доставки кадров, не измерение физической развёртки монитора.

[Облачные результаты](validation/0.14/README.md) относятся к Mono/Xvfb и **Mesa llvmpipe**, программному OpenGL на CPU. Они подтверждают работу нового пути и находят регрессии, но не подтверждают 60–165 FPS на Windows/RTX. Для этого нужен прогон того же приложения с аппаратным Windows-драйвером; скрывать оставшиеся выбросы средним FPS нельзя.

## Зависимости

В `lib/` закреплены OpenTK и OpenTK.GLControl **3.3.3**, совместимые с .NET Framework 4.7.2. Источник — публичный NuGet (`opentk/3.3.3` и `opentk.glcontrol/3.3.3`, `lib/net20`), [исходники релиза](https://github.com/opentk/opentk/tree/3.3.3). `OpenTK.dll.config` содержит сопоставления нативных библиотек для Mono; Windows использует системный OpenGL. Лицензия MIT и дополнительные уведомления находятся в `lib/OpenTK-LICENSE.txt` и в игровом архиве. SHA-256 исполняемого файла, зависимостей и исходников записываются в build-receipt; упаковщик отклоняет отличающиеся бинарники.
