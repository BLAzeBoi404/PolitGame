# Проверки SOVEREIGN 0.16

Сборка: .NET SDK 8.0.426, Release net472, без ошибок и предупреждений компилятора. Исполнение: Mono/libgdiplus на Linux; интерфейс — Xvfb; графический путь — настоящий OpenGL-контекст Mesa llvmpipe, исполняемый на CPU. Нативная Windows и аппаратная видеокарта здесь не проверялись.

## Проверки окончательного исполняемого файла

- `tests-sdk.txt`: **695 успешных проверок**, 0 ошибок. Сохраняется весь прежний набор экономики, торговли, войн, начальных сценариев, технологий, мобилизации, госзаказов и многолетних кампаний. Добавлены **47 проверок подготовки и усталости**.
- Проверены точное ежедневное списание денег, топлива и вооружения; отсутствие авансового опыта; повторные команды и повторный расчёт дня; отмена без возврата; пауза при нехватке каждого ресурса; ограничение опыта; запрет совмещения с начальным обучением и назначения чужой части.
- Завершён полный оплаченный курс, проверены последующий отдых и сохранение опыта. Настоящий приказ прекращает учения, отклонённый приказ их сохраняет. Реальный бой утомляет обе стороны; фактическая боевая сила снижается, критически истощённое наступление останавливается.
- Проверены длительность войны, однократный учёт реальных потерь, влияние на выпуск/пополнение/боевую силу и постепенное восстановление после мира. Сохраняется баланс личного состава.
- ИИ обучает часть войск за реальные деньги, оставляет другие части доступными, сразу прекращает курсы при нападении, меняет настоящую цель импорта. Отдельные сценарии проверяют снабжённую сильную армию, отсутствие топлива/вооружения, усталость страны, дефицит бюджета и оборонного союзника цели.
- Сохранение и загрузка воспроизводят **полный сериализованный результат 35 последующих дней**, включая торговлю и ИИ. Миграция формата 13 сохраняет деньги, опыт и расположение, не начисляет старые потери задним числом. Некорректные значения и сроки отклоняются.
- `previous-release-save.txt`: кампания после 765 дней создана исходным SDK exe **0.15**, затем загружена и продолжена ещё 30 дней окончательной 0.16. `legacy-save.txt`: аналогичная проверка исходного пользовательского сохранения. Источники не перезаписываются.
- `ui-results.txt`: **543 проверки**, 0 ошибок. Настоящие клики открывают ведомость, запускают/останавливают курс, соблюдают ограничения и переходят к закупкам. На 1280×720, 1600×900 и 1920×1080 проверены доступность и отсутствие перекрытий элементов. Снимки `readiness-*.png` получены из игры.
- `gpu-results.txt`: **25 проверок**, 0 ошибок. В том числе новая ведомость, прежняя торговля, география/масштабирование, ввод, повторное использование HUD и текстур при движении, фоновая симуляция, очередь действий/сохранения и закрытие. `gpu-readiness.png` снят из GPU framebuffer.

`build-receipt.json` содержит хеши исходников, exe и библиотек. Упаковщик проверяет их и требует успешные отчёты. Диагностический пробник, временные XML, личные сохранения и настройки в архив не включаются.

## Методика производительности

База: исходный SDK exe 0.15 из коммита `69d1480b5054cd47ade7121651a2a9d28027b0f7`, SHA-256 `51dbb484f7a006d8fd4769f62f19b0d54efc2f63e0799714bb5e2ca377654137`. [SimulationProbe.cs](../../../scripts/SimulationProbe.cs) без изменения с прошлого выпуска компилируется отдельно против каждой версии.

Сценарий: Украина, 2026, обычная сложность, все 176 стран, 4 136 областей и полный сценарный состав сил; 35 дней прогрева + 730 измеряемых дней; UI и автосохранение выключены. Три последовательные пары 0.15 → 0.16, без одновременных сборок или тестов. Измеряются среднее, p50, p95 и максимум, отдельно для недельных и остальных дней. В конце кампания проходит валидацию.

Изменение решений ИИ, потерь, подготовки и экономики меняет траекторию мира: в конце сравнения 3 688 соединений в 0.15 и 3 720 в 0.16. Это одинаковый стартовый сценарий, но не тождественные состояния каждый день. Облачный хост также даёт выбросы; все три результата сохранены, включая медленный третий запуск 0.15.

## Найденное узкое место

Первый вариант (`simulation-initial.txt`) дал в среднем 34,76 мс на недельный день. Временная инструментированная сборка (`profiling-initial.txt`) показала 16,16 мс на планирование подготовки, из них 13,82 мс на проверки кандидатов. Каждый вызов повторно проверял отпечаток всех областей и договоров сети снабжения и искал ту же часть по общему списку.

Общая проверка и запуск учений теперь принимают саму часть и одну актуальную сеть снабжения на весь проход ИИ. Условия обучения не ослаблены, отдельный скрытый путь для ИИ не появился. В течение этого прохода владельцы областей и договоры не меняются. Ежедневное состояние считается один раз, планирование — раз в неделю, а не каждый кадр карты.

## Окончательные результаты

Медианы средних и p95 по трём прогонам; максимум — худший из трёх. Время в миллисекундах. Это стоимость дня симуляции, **не FPS монитора**.

| Дни | 0.15: среднее / p95 / максимум | 0.16: среднее / p95 / максимум |
| --- | ---: | ---: |
| Все | 9.05 / 19.97 / 390.08 | 10.54 / 26.53 / 120.34 |
| Недельный расчёт | 16.63 / 22.09 / 140.97 | 21.56 / 33.31 / 120.34 |
| Остальные | 7.84 / 13.96 / 390.08 | 8.71 / 17.09 / 118.41 |

Средний день: 9,05 → 10,54 мс (около +16,4%); недельный: 16,63 → 21,56 мс. После устранения повторных проверок новый расчёт всё ещё дороже прежнего. Дополнительную стоимость подготовки и иное развитие мира нельзя выдавать за полностью неизменившуюся производительность.

В существующей пятилетней проверке 0.16 рассчитала 1 825 дней за 18,12 с, сохранив валидный мир с 3 667 соединениями; старый отчёт 0.15 содержал 15,02 с и 3 442 соединения. Это вспомогательное непарное сравнение. Максимумы текущих пар доходят до 120 мс у 0.16 и 390 мс у 0.15; различия выбросов облачного хоста не подтверждают улучшения задержки на пользовательском компьютере.

GPU-режим продолжает считать день вне потока окна и сохраняет готовые слои карты. Проверка удерживаемого worker подтверждает возможность презентации камеры во время расчёта. Нативные Windows-драйверы, реальный FPS 60–165 и большие войны на поздних стадиях требуют отдельного аппаратного замера.
