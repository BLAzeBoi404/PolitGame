# Проверки версии 0.13

Итоговый SDK exe: **603 проверки логики и 515 интерфейса, ошибок нет**. Release net472 собран без предупреждений. Выполнение — Mono/libgdiplus/Xvfb в Linux; физический Windows и его FPS не проверены. Хеши исполняемого файла и всех исходников/встроенных таблиц записаны в `build-receipt.json`; упаковщик сверяет их перед созданием ZIP.

Проверены точный выбор всех 4 136 опорных точек, внутренние точки и перекрытия 40 районов Молдовы, реальные щелчки мышью, масштаб 400, камера столицы, группировка и переключение частей, ограниченный кэш и повторные проходы без перестроения. Снимки `scenario-moldova.png` и `scenario-russia.png` получены именно итоговым exe. Подписи размещаются в общей системе координат, чтобы не обрываться на границах тайлов.

Проверены национальные суммы населения, размещение гарнизонов, отсутствие случайной части на Чукотке, разные размеры и классы соединений, точное сохранение личного состава и малых значений населения. Полный мир проходит ежедневную симуляцию и пятилетнюю проверку: 1 825 дней за 18,67 с в этом запуске. Исправное оснащение не тратит ремонтные материалы, повреждённое — тратит. Встроенные проверки существующих исследований, доктрин, закупок, экономики, авиации и политики также проходят.

Предоставленное старое сохранение и отдельная кампания, созданная **оригинальным exe 0.12** после 30 дней, загрузились и прошли ещё 30 дней. Контрольные суммы исходных сохранений не изменились. Три сценарные таблицы воспроизведены из включённых входов побайтно (`scenario-rebuild.txt`). Само личное сохранение в Git и ZIP не включено.

## Производительность

Одинаковые камеры, 1600×900, высокое качество, нативный размер растра. База — исходная сборка 0.12 из коммита `03fc466b0213f1753111a61a19501fd1fee4bd66`, SHA-256 `45ab6b20f903b7123b6c4c2ec2d3fc18448c2e2c96f548451e3f27f73aac1553`. После первых замеров выполнены **три последовательные пары** 0.12 → 0.13; сохранены все результаты, включая первые. Таблица показывает медианы по трём парным запускам, а не лучший результат.

| CPU: ввод + отрисовка | Среднее 0.12 → 0.13, мс | p95 0.12 → 0.13, мс |
| --- | ---: | ---: |
| Длинное панорамирование, средний масштаб | 9,14 → **4,19** | 16,89 → **5,27** |
| Неподвижная карта, много областей | 4,89 → 4,48 | 6,02 → 8,15 |
| Короткое движение в готовом кэше | 3,48 → 3,95 | 5,35 → 5,37 |
| Наведение и точный выбор | 3,58 → 3,98 | 4,32 → 5,08 |
| Ресурсная карта с расчётом дня | 7,51 → 12,14 | 17,70 → 23,11 |
| Семь дней одним тестовым пакетом | 39,32 → 59,55 | 78,93 → 95,25 |

Ускорен прежде всего проход через новые участки карты. Неподвижные и короткие проходы не стали быстрее во всех случаях. Новый мир содержит **3 765 соединений вместо 517**, поэтому симуляция тяжелее; игра рассчитывает дни отдельно между обработкой ввода, а не тестовым пакетом из семи дней. Убраны повторные массивы характеристик техники и временные объекты расчёта поддержки: число GC0 в тесте 140 дней снизилось примерно с 187 до 27 по сравнению с промежуточной сборкой 0.13, формулы не изменены. Большие войны и месячные расчёты остаются предметом дальнейшего профилирования.

Отдельный `--pan-benchmark` использует настоящий цикл сообщений WinForms и синтетические события мыши. Во второй паре запусков повторный проход:

- 0.12: 116 перестроений снимка, 44 кадра с резервной подложкой, интервалы Paint среднее 18,29 / p95 24,74 / максимум 50,72 мс.
- 0.13: **0 новых тайлов, 0 кадров с резервной подложкой**, интервалы Paint среднее 21,26 / p95 22,74 / максимум 29,55 мс.

Средний интервал Paint не улучшился: это обновления по запросу, в том числе уведомления от фоновой подготовки, а не счётчик кадров физического монитора. В первом проходе сохранялись единичные большие задержки (до 190 мс в последнем запуске 0.13). Поэтому отчёт **не утверждает полного устранения просадок или достижения 60 FPS на Windows**. Повторный проход подтверждает устранение постоянной перерисовки географии и размытия просмотренных участков. Настройки пользователя после нового диагностического режима восстанавливаются, что проверено по хешу файла.

Полные результаты: `performance-summary.txt`, `performance-{before,after}-run{1,2,3}.txt`, первые `performance-before.txt` / `performance-after.txt`, обе пары `pacing-*.txt`. Динамика общей загрузки CPU сама по себе не выявляет ограничение отдельного потока WinForms/GDI+; реальный Windows-тест остаётся необходимым для оценки пользовательской плавности.
