# Проверки Sovereign 0.9

Проверен именно `bin/Release/net472/Sovereign.exe`, собранный .NET SDK 8.0.426 / Release net472 без ошибок и предупреждений. Исполнение — Debian 13 / Mono 6.12 / libgdiplus / Xvfb. Реальный Windows 10/11 и удалённый GitHub Actions в этой сессии не проверены.

## Функциональные результаты

- **334 проверки логики**, `Failures: 0`. Прежние системы, 72 достижимых технологии, уникальные узлы и направленные связи, все положительные коэффициенты при полной науке, настоящая очередь почвоведение → орошение → удобрения → зелёная революция, реальный выпуск с увеличением расхода топлива, потери после медицинских открытий, восстановление организации после радиосвязи и настоящий наземный бой с общевойсковым бонусом.
- **287 проверок интерфейса**, `Failures: 0`. Настоящие события WinForms. Все 72 карточки нажаты в размерах 1280×720, 1600×900 и 1920×1080; проверены обзор, перетаскивание, потеря захвата мыши, колесо и переходы между предпосылками. Отдельные проверки подтверждают, что дерево не двигает карту под ним и что новый узел запускает реальное исследование.
- Проверка кэша подтверждает отсутствие перестройки неизменной ресурсной карты при смене дня и обновление после настоящего изменения ресурсов или инфраструктуры. Таймер проверен на один день за вызов, отсутствие накопленного догоняющего цикла, паузу и интервал 650 мс при нормальной скорости.
- Миграция формата 7 в 8 сохраняет прежние открытия, активный и отложенный прогресс, очередь, паузу, деньги и RNG. Новые 48 флагов изначально пусты. Новые открытия переживают запись и загрузку. Прежний тест побайтово одинаковых кампаний после 150 дней также проходит.
- Исходное пользовательское сохранение из ZIP и сохранение 0.8 с прикладной наукой загружены и продолжены на 30 дней; оригиналы не перезаписаны.
- Длинный сценарий: `1825 days, 176 countries, 4136 provinces, 574 formations: 5.24 seconds`. Это встроенный сценарий, не предел масштабной войны; его время получено одновременно с другими функциональными проверками.

## Сравнение производительности

Обе версии собраны **одним .NET SDK 8.0.426 в Release**. База — коммит 0.8 `52d573d`, распакованный в отдельную временную папку без изменения текущего репозитория; добавлены только идентичный измерительный модуль и вход `--benchmark`. Хеши обеих сборок, исходников и измерительного модуля приведены в `build-receipt.json`.

Одинаковая камера и размер 1600×900; два последовательных прогона пары «до/после», без параллельных тестовых процессов. В таблице — среднее время двух прогонов. Измеряется CPU-время обработки ввода и рисования в bitmap; это **не FPS дисплея** и не замер на Windows.

| Сценарий | 0.8, мс | 0.9, мс |
|---|---:|---:|
| Кэшированный политический кадр | 3.26 | 3.71 |
| Наведение с точным попаданием | 3.62 | 3.82 |
| Выделенная сложная область | 13.00 | 15.95 |
| Перетаскивание карты | 3.42 | 3.64 |
| Полная перестройка карты | 64.97 | 35.88 |
| Ресурсный слой при смене дня | 114.88 | 6.24 |
| Научная ведомость (24 → 72 технологии) | 5.56 | 6.25 |

Главный подтверждённый выигрыш — обновление ресурсного слоя и полная перестройка географии. Кэшированные кадры, наведение и перетаскивание существенно не ускорились. Выделение сложной области также не показало устойчивого выигрыша; в одном прогоне зарегистрирован максимум **161.92 мс**, сохранённый в исходном отчёте. Причина единичного выброса не установлена; результаты не подтверждают постоянные 60 FPS. Новая научная ведомость рисует более сложный граф, поэтому сравнение её времени показывает стоимость добавленного интерфейса.

Отчёты `performance-before.txt`, `performance-before-2.txt`, `performance-after.txt`, `performance-after-2.txt` содержат также p95 и максимум. Искусственный семидневный пакет оставлен в измерителе для диагностики; игровое окно больше не вызывает такую пачку. Его результаты не используются как доказательство ускорения симуляции: поведение ИИ после расширения науки меняется. Тяжёлый игровой день, большой скачок камеры и автосохранение по-прежнему могут задерживать интерфейс.

Воспроизведение текущего замера: `source /workspace/tooling/env.sh`, затем `bash scripts/with-display.sh mono bin/Release/net472/Sovereign.exe --benchmark artifacts/performance.txt`. В Windows: `Sovereign.exe --benchmark performance.txt`. Для базы извлеките исходники `52d573d`, добавьте текущий `GameForm.Performance.cs` и только обработку аргумента `--benchmark` из `Program.cs`, соберите тем же SDK и запустите тот же сценарий.
